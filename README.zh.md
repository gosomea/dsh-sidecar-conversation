# dsh-sidecar-conversation

**把主会话中的一段内容，展开成旁边可持续的对话。**

在 DeepSeek Harness Web 中，你可以选中一段回答、针对整个回合继续追问，或从某个旧回合分叉。侧问在原生右侧栏里聊天，拥有自己的消息、草稿、模型和权限；主会话仍留在原处。

[English](./README.md) · [GitHub Release](https://github.com/gosomea/dsh-sidecar-conversation/releases/tag/v0.2.1) · [npm](https://www.npmjs.com/package/dsh-sidecar-conversation)

## 可以怎样用

- **解释一段回答**：圈出不理解的文字，带着引用在旁边追问。
- **继续已有侧问**：把新的选文或整个回合追加到最近使用的侧问，保留正在编辑的问题。
- **从旧回合换个方向**：Fork 当时的上下文，主会话继续原来的工作。
- **只带引用重新开始**：创建独立会话，使用明确选中的内容和新问题，不继承整段聊天历史。

右侧聊天复用 DSH 原生输入框：支持上传文件、选择模型和推理等级、调整权限，以及原生消息、工具调用、审批、停止和错误展示。侧问可以持续多轮，不是一次性的弹窗问答。

## 两个入口，相同的选择

在已完成的 Assistant 回答中拖选文字，或点击回合末尾的「侧问这个回合」，都会打开操作菜单。

| 菜单选项 | 选文入口 | 整回合入口 |
| --- | --- | --- |
| 追加到最近侧问 | 向目标草稿添加这段选文 | 向目标草稿添加整个回合引用 |
| 仅用选文新建／仅用此回合新建 | 新会话只带这段选文 | 新会话只带该回合的最终 Assistant 回答 |
| 从此回合 Fork | 继承截至选文所属回合的历史，并带上选文引用 | 继承截至该回合的历史，并带上回合引用 |

只有当前主会话下存在已创建、标签尚未关闭的侧问时，才显示「追加到最近侧问」。因此菜单是两个新建选项，或加上追加后的三个选项。右侧栏收起但标签仍打开时，追加会重新展开并切到目标侧问；已关闭标签和未准备完成的草稿不参与选择。

创建方式在左侧菜单里确定。选择新建时就准备对应 Session，右侧直接打开原生输入框；不必再选一次，也不会在准备时自动调用模型。新草稿只带这次来源，不复制其他侧问的选区。

## 从引用到多轮聊天

1. 在左侧选择文字或回合，并决定追加、独立新建或 Fork。
2. 在右侧编辑问题，按需上传文件、选择模型与权限。可以继续从左侧逐项添加引用，也可以移除草稿中的某一项。
3. 点击草稿引用，可回到来源消息并高亮；发送后，历史消息里的引用仍然可以点击定位。
4. 发送后继续在当前侧问聊天。切换主会话、关闭重开或刷新页面，会按各自子 Session 恢复内容，避免串选区或跳回旧侧问。

选文最多 4,000 字符。「整个回合」引用指向该回合的最终 Assistant 回答；独立会话带入的是这条明确引用，只有 Fork 才继承之前的聊天历史。来源被删除或无法读取时会提示错误并保留引用。

## Fork 与独立会话

| | 关联侧问（Fork） | 独立新会话 |
| --- | --- | --- |
| 上下文 | 继承到所选回合为止的主会话历史 | 只接收明确添加的引用和问题 |
| 原生关系 | 主会话的子 Session | 无原生父会话，与主会话同级 |
| Fork 进度 | 显示分叉回合和落后轮数，可跳转来源与最新主回合 | 提示仅带入引用，没有 Fork 差距 |
| 历史入口 | 列在来源主会话的侧问历史里 | 同样可从来源会话的侧问历史找回 |

Fork 是分叉时的上下文，不会实时追随主会话。主会话继续产生回合时，右侧提示会更新；追加新引用不会减少落后轮数，也不会自动合并之后的主会话历史。

两种会话都沿用来源工作区。菜单新建默认只读，之后通过原生选择器调整权限；允许写入的工具会修改同一工作区文件。只读不表示网络隔离。侧问消息保存在自己的 Session 中，不自动写回主会话。

## 标题、历史与恢复

初始标题取首次问题摘要。创建后，左侧列表、右侧标签和侧问历史读取原生 Session 标题；手动重命名会同步。关联侧问通过原生行首的 `↳` 和悬浮信息标记，原生运行状态标识优先显示。历史由插件内的只读适配器读取现有工作区视图 store，同步手动顺序、最近更新、置顶和工作区分组；折叠分组不会隐藏历史条目。

「侧问历史」提供新建、重新打开、归档和恢复。关闭标签只关闭视图，不会停止后台生成；归档是插件历史状态，不删除原生会话。历史新建从主会话最近一条已完成回答开始，仍可选择 Fork 或独立会话；还没有已完成回答时会提示先完成一轮。

正文、回复、附件和工具事件使用 DSH 原生 Session 能力。侧问索引保存在 `sidecar-conversation.json`，草稿和标签布局属于浏览器状态。清除浏览器数据后，已发送对话可从历史重开；未发送草稿无法靠 session log 恢复。[原生 session log 的职责与升级边界](./docs/native-session-log.md)

## 安装前先确认 DSH 兼容性

版本 `0.2.1` 使用未修改的官方 npm DSH `0.2.1-alpha.3` API，无需修改 DSH 源码或安装 Better Sidebar：

- `sidebar.session.row.leading` / `sidebar.session.row.hover`：已有的公开行装饰插槽；标题继续使用原生实现。
- `sidebar.workspaces` / `shell.overlay`：通过公开插槽账本复用现有 root 视图 store handle，只读偏好，不另存排序，也不替换原生列表。

不再使用定制的 `uiWorkspace.sessionOrder` 和 `sidebar.workspaces.session.title` 扩展。标题、输入框、引用及 session log 保持原生实现。父子行折叠是定制 DSH 的独立能力。[完整兼容性说明](./docs/compatibility.md)

源码开发时，通过 DSH Web profile 安装本地构建的插件：

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm build
dsh plugin --profile web add link:$(pwd)
dsh --profile web --dump-config
```

安装后重启目标 Web 实例。`--dump-config` 只证明配置组合成功；还应打开页面确认插件运行。联调构建应使用独立 DSH_HOME、端口和插件目录，避免影响日常实例。卸载使用 `dsh plugin --profile web remove dsh-sidecar-conversation`。[开发与验证方法](./docs/development.md)
